"select" evaluates every case before choosing one.

On entry, each case's channel expression and each send's value are evaluated once, in source order.
Then one ready case is picked at random, and only its send or receive runs.
Side effects of the evaluation happen even for cases that are not picked (Go spec).


Common mistake: case <-time.After(d) creates a new timer on every entry,
so in a for loop the timeout restarts each iteration (golang/go#70821).
Before Go 1.23, the losing timers also stayed in memory until they fired.

	for {
		select {
		case m := <-msgs: // a message arrives every second
			fmt.Println(m)
		case <-time.After(5 * time.Second): // a new 5s timer on each iteration: never fires
			fmt.Println("timeout")
			return
		}
	}

Fix: create the timer before the select; keep cases to plain channels (ch, ctx.Done(), timer.C).
